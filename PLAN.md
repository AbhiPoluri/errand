## 0. What it is

**Errand** — "A calm desktop helper that does real work on your files: pick a common
job from a card or just say what you need, watch it happen one plain-English step at a
time, and approve anything that changes your stuff before it happens."

- **Audience:** non-technical adults who won't read docs, don't understand JSON/logs/tokens/"tools"/model names, fear breaking things or losing data, and need to trust the helper at every step.
- **v1 scope:** local-only, single-user, runs on the Mac via `next dev`. One Next.js process; the hand-written harness runs server-side in a Node-runtime route handler (real fs + child_process; `OPENROUTER_API_KEY` never reaches the browser).
- **v1 capabilities:** sort/organize a folder, gather files into a new folder, batch rename, find duplicates, read & explain documents, summarize what changed, free up space.
- **Every destructive action is reversible-by-construction** (delete = move to a Review folder; overwrite = snapshot prior bytes) and **gated behind a plain-language approval**.
- **Out of v1 scope:** hosting/multi-user, parallel tool calls, sending email/money/posting, multi-tab parallel errands.

**Chosen paradigm:** Vision C hybrid — a calm Home (recognition cards + one persistent text box) where BOTH paths funnel through one **Plan Preview** into one full-screen **Run View** — with Vision A/B's strict safety (gate *every* mutation, no silent fast-path) and conversational discipline applied inside the Run View timeline.

## 1. The 10 UX principles (non-negotiable)

1. **Recognition before recall, on one screen** — example-errand cards teach what's possible; a persistent text box accepts anything; both funnel through the SAME Plan Preview → SAME Run View. The typed path inherits the FULL guardrail pipeline, never a degraded one.
2. **Intent preview before acting** — show the plan in plain future-tense words with exact scope named, before anything starts. Target >85% accept-without-edit.
3. **Ask permission in human terms before EVERY mutation** — any write/move/rename/delete/overwrite/network action pauses and asks with consequence + exact count + real filenames + "Show me the list" + a safe default (focus on "Not yet"). "Reversible" is reassurance copy, never a license to skip the ask. Batched by logical operation, never 30 cards, never a silently-split destructive batch.
4. **Reversibility is built, not promised** — deletes → move-to-Review-folder; overwrites snapshot prior bytes; moves/renames record their inverse. Undo renders ONLY for ops the journal recorded as cleanly reversible; otherwise greyed with the limit stated plainly.
5. **Zero jargon, ever** — no JSON, logs, tokens, model names, the word "tool", stack traces, error codes, or even the word "error" on any user surface. A single jargon leak is a **sev-1 bug**.
6. **Progress is continuous, honest, duration-matched** — a big present-tense "now doing" sentence + a growing past-tense timeline with real counts. Step counter only for known templates (labelled "about", never shrinking); honest "Working on it…" shimmer otherwise. The agent VISIBLY pauses (ring stops, bar holds, timer freezes) when waiting on the user — the single most important trust signal.
7. **Frictionless exit and recovery** — a persistent Stop that promises an outcome (never silent hard-abort mid-move); every error is a calm blame-free sentence stating what is/isn't affected, plus a concrete next button. Never a dead end.
8. **Pre-flight the real world** — before the Run View, check OS permission (Full Disk Access), scope folders exist & are writable, external drives mounted — so failures happen calmly at Plan Preview, pre-commitment.
9. **Predictable placement (VARIANCE 3)** — status sentence, progress bar, timeline, Stop, and the permission slot occupy the same position every run. Muscle memory within one use.
10. **Two-root scope, visibly bounded** — a job reads from a source root and writes to a dest root; BOTH named in Plan Preview and every approval. Honest bounded scope.

## 4. Architecture (harness → UI)

React + Next.js (App Router) + Tailwind + TypeScript. **The hand-written harness is built UI-agnostic from line one** — NOT wrapped later. The repo is verifiably v0 (transport only: client.ts/config.ts/checkModel.ts/v0.ts; loop/session/tools/log are unbuilt).

- **Transport only:** the `openai` SDK (baseURL openrouter.ai/api/v1) does HTTP/auth/streaming and nothing else. Loop/tools/Session/context are hand-written.
- **Where it runs:** server-side INSIDE Next.js, in a `export const runtime = 'nodejs'` route handler (NOT edge — bash/file tools need real fs+child_process; key must never reach the browser).
- **The loop emits a single discriminated-union `AgentEvent`** (`src/events.ts`, the shared contract) through an injected **EventSink** — it NEVER calls console.log or returns strings to the UI. **Two sinks prove UI-agnosticism:** a headless CLI renderer and a web sink that serializes events to SSE.
- **UI ↔ harness:** **SSE** for the server→client run stream (`POST /api/runs` → runId; `GET /api/runs/[runId]/stream` is an EventSource; heartbeats ~10s survive long reasoning gaps; every event sets SSE `id:` = seq for Last-Event-ID dedupe). **Plain fetch POST** for discrete controls: `/decision` (approve|deny), `/cancel` (→ AbortController), `/message` (next user turn into the same Session). SSE over WebSocket because traffic is ~95% server→push.

### The 4 gating engineering items (the visions depend on these; v0 lacks them all)

1. **Operation journal + reversibility engine** (`src/journal.ts`) — every mutating tool records `{op, inverse, before-state}` on the Session. DELETE = move to `.errand-review/<runId>/` (never `unlink`). writeFile snapshots prior bytes or refuses overwrite. ONLY a tool that recorded an inverse may set `reversible: true`; the UI renders Undo ONLY for journaled-reversible ops. **Ships BEFORE any "Undo" copy.**
2. **Approval-exit ordering invariant** — OpenAI format requires every assistant `tool_call` id to be followed by a matching tool result or the next request 400s. The assistant message carrying tool_calls is already in `session.messages` when the gate fires, so EVERY non-approve exit (denied, cancelled, idle-expired, SSE-disconnect-reaped, throw-while-parked) MUST append a synthetic tool result `{ok:false, reason}` for the parked call AND its siblings. The approvals resolver resolves a discriminated decision (`approved|denied|cancelled|expired`) and **NEVER `reject()`s** (a reject would throw mid-for-loop and strand a tool_call). This is what makes suspend-on-Promise resume actually correct.
3. **Narration contract** — per-tool `describe(args) → {action, detail?, items?, consequences?, reversible}` (before run; drives `tool.proposed`/`approval.required`) and `summarize(result) → string` (after; drives `tool.result`), co-located with each tool. A deterministic allowlist of approved verb templates + a hard "Working on it" fallback that NEVER emits a raw tool name/finish_reason/token. `bash` describe() parses actual argv; un-parseable shell (glob/pipe/substitution) is treated as maximally-irreversible (shows exact command, labelled "I can't predict exactly what this will change").
4. **Pre-flight OS/scope check at Plan Preview** — Full Disk Access, folder exists+writable, drive mounted — so OS dead-ends fail calmly before commitment.

### Streaming / reasoning specifics

- Separate `delta.content` → `message.delta` from OpenRouter's **untyped** `delta.reasoning` → `thinking.delta` via ONE normalization helper that ALSO probes `delta.reasoning_content` (DeepSeek key) and tolerates interleaving (order-independent dual buffers; `thinking.summary` on first-content-OR-finish).
- `delta.refusal` is a first-class SDK Delta field → add a `message.refusal` event so a streamed refusal resolves the Thinking pulse instead of hanging forever.
- `parallel_tool_calls: false` is an ARCHITECTURE INVARIANT (a "length" cut during parallel calls corrupts per-index partial JSON).
- `finish_reason: 'length'` = a clean `run.error` ("had to stop early, nothing was changed"), never a silent partial.
- **State:** a `SessionStore` interface (InMemory for v1 — the only hosting seam) holds the Session (messages never recreated per turn); a `RunRegistry` (runId → {abortController, pendingApprovals, sink, ring buffer}) lets /cancel and /decision reach the parked loop + supports refresh-replay. The JSONL trace (`src/log.ts`) is the ONLY home for raw args/results/errors/usage/finish_reason, and the v6 resumable-transcript seam.

### AgentEvent protocol (the shared contract)

`run.started` · `turn.started` · `thinking.delta` · `thinking.summary` · `message.delta` · `message.refusal` · `message.completed` · `tool.proposed` · `approval.required` (loop PAUSES) · `tool.started` · `tool.result` (ok true/false) · `approval.resolved` (approved|denied|cancelled|expired — never reject) · `run.error` (plain reassuring userMessage, stack only in trace) · `run.finished` (status + changes[] driving SummaryCard + Undo) · `heartbeat`. Every non-heartbeat event carries `{runId, turnId, seq, ts}` and sets SSE `id: = seq`.

### New files
`src/events.ts`, `src/loop.ts`, `src/session.ts`, `src/journal.ts`, `src/tools/{index,echo,bash,readFile,writeFile,move,delete}.ts` (each with describe/summarize + gated/reversible), `src/log.ts`, `src/server/{sessionStore,runRegistry,webSink}.ts`, `app/api/runs/{route, [runId]/stream/route, [runId]/decision/route, [runId]/{cancel,message}/route}.ts`, `app/page.tsx`, `app/components/{RunTimeline,ThinkingDisclosure,ApprovalCard,ProblemCard,SummaryCard,StepRow,states/{Skeleton,Empty,ErrorCard}}.tsx`, `app/lib/useRun.ts`; `src/cli.ts` kept as the second sink.

## 7. Open risks (carried, watch continuously)

- **Every runtime correctness claim is unverified until the loop runs** — suspend/resume, message ordering on non-approve exits, streaming delta accumulation. The v2 integration test is mandatory and catches the biggest resume bug.
- **Undo is only as real as the journal** — a "reversible" move that collides with an existing destination filename, or an un-cleanly-reversible rename, means acted-but-can't-undo (worst case). Mitigation: move-into-existing-destination is itself treated as overwrite (gated + snapshotted); Undo renders ONLY for clean-inverse ops.
- **The narration layer is the product and the model writes the sentences** — a single jargon leak on first use breaks trust permanently. Mitigation: system-prompt contract + deterministic verb-template allowlist + hard "Working on it" fallback; any leak is sev-1.
- **`delta.reasoning` is an untyped extension** with unspecified ordering; other models use `delta.reasoning_content`. Mitigation: one normalization helper probes both, order-independent buffers, generic "Thinking…" fallback.
- **In-memory store/registry lose live runs + parked approvals on dev restart / second worker.** Now handled GRACEFULLY (2026-06-17): boot-time `reconcileOrphans()` turns any zombie `working` run into a clean interrupted state (parked approvals cancelled, terminal event appended, status `stopped`), and runs are continuable after restart via rehydrate. True hosting-grade durability (resume a run mid-flight, multi-worker) still wants the store/registry swap — but the UI no longer hangs and no run is silently lost.
- **Free-tier latency/rate-limits attack the "never frozen" feel** and can strand a run; heartbeats fix transport, not perception. Also: KV-cache is gone after a long approval pause → resume re-processes a large prompt (latency/cost cliff). Mitigation: intermediate narration + (recommended) paid fallback on the Run View.
- **Approval fatigue** — a big destructive job flooding the timeline trains rubber-stamping. Mitigation: deterministic batching by logical operation is a LAUNCH requirement, never a later tuning pass; a destructive batch is NEVER silently split into singles.
- **OS-level dead-ends** (Full Disk Access, locked files, unmounted drives) can't be fixed by the app. Mitigation: Plan-Preview pre-flight + illustrated Settings card; accept a known abandonment risk; consider a "show me how" walkthrough for Full Disk Access.
- **Two renderers = the AgentEvent protocol is now a real API surface.** Mitigation: discriminated union + exhaustive never-default switch forces both CLI and web to handle every event at compile time.
